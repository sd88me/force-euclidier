## Feature summary of upstream (for reference)

8 lanes. Per lane: enable, pitch (0–127), time division (11 values), steps 2–64, fill 1–64
(Bjorklund/Euclidean), shift 0–64, loop point (0=off; < steps shortens; > steps gives polyrhythm),
gate 10–95%, out MIDI channel 1–15 (16 = feedback), base velocity, value-alt (humanize 0–50 in note
mode), track mode (1 note, 2 drum, 3/4 CC). Globals: internal/external clock, start/stop, BPM1+BPM2,
master-sync quantize (CC 50, 0–8 bars), 128 preset slots (CC 20 select, 29 load, 30 save, program
change loads; feedback to the controller on ch 16), randomizer (CC 90 go, CC 89 lane select: 0 all,
1–8 lane, 9 all-but-1, 10 all-but-5), receive-notes (CC 99), velocity-sense octave shift (CC 119),
reset transpose/octaves (CC 100), sync-all (CC 70), realtime note transpose (notes 0–95) and octave
shift (notes 96–127). Full CC map: upstream `README.md` "Midi Mapping". Two virtual MIDI ports
("Euclidier"), no GUI upstream. Preset bank file: `euclidierBANK.bin`. Chord-pad progression files
in `Euclidier Progressions/`.

## A. Engine rework: stateless step position (removes stop/start resync)

**Why resync is needed today.** Each `EQSEQ` keeps its own step counter (`_step`, `sstep`).
Any change to steps/fill/shift/div goes `updateSeq()` -> `sync()` (zeroes `_step`, kills hanging
notes), then `processQ()` calls `resync()` on all lanes. Lanes only re-align when the transport
restarts.

**Fix.** Count clock ticks since transport start and derive position each tick:

```
ticksPerStep = 96 / getDiv(div)     // every getDiv() value divides 96 evenly
n            = tickCount / ticksPerStep
k            = n % (loop ? loop : steps)
idx          = k % steps            // loop > steps => polyrhythm, same as today's behaviour
fire if SEQ[idx]
```

Position is a pure function of the Force's clock, so changing steps/fill/shift/loop/div only
rebuilds `SEQ` (and changes the modulus); lanes stay phase-locked.

Transport: 0xFA start (tick=0), 0xFB continue, 0xFC stop, 0xF2 song-position-pointer (set
tick = SPP*6 on continue/locate), 0xF8 clock. Verify the Force actually sends 0xF2 on locate
before relying on it.

Remove: `autosync` / CC 80 behaviour, `doSync`, `resync()`, `sync()` resets on edit. Keep
`killHanging()` only for mute, MIDI-channel change, mode change and transport stop.
Master-sync quantize (CC 50) stays as an **optional** "apply edits on bar boundary"; default
should be immediate now that it is safe. A division change is aligned to the tick grid but the
step phase jumps (n changes) — acceptable, note it.

Files: `eqseq.cpp` (`tick`, `updateSeq`, `sync`, `reset`, `setGATE`), `euclidier.cpp`
(`pulse`, `resync`, `processQ`, `clockStart/Stop`, CC 80/70 handlers).

## B. CPU reduction (upstream: ~2–3%)

Cause: main loop `usleep(100)` (~10k wakeups/s) while running, `usleep(5000)` while stopped —
existing only to time note-offs.

- Event-driven note-offs: small sorted pending-off list; sleep until the next deadline
  (`clock_nanosleep` / `timerfd` / condvar), block indefinitely when nothing is pending.
- Note-ons fire from the MIDI-clock callback.
- `steady_clock` instead of `system_clock`; no `printAll` console redraws in `-v` (background) mode;
  replace vector-erase BPM averaging with a running average.
- Add a mutex: RtMidi's callback thread and the main loop both touch `QUEUE`/`WAIT_QUEUE` and lane
  state with no locking today.
- Target: well under 0.5%. **Estimate only — measure with `top`/`/proc/<pid>/stat` before/after.**

## C. Dormant features (kept in code, default off, hidden from GUI)

- **CC track modes (3, 4)**: leave `EQSEQ` mode-3/4 code paths and CC 111–118 handling intact.
  Lanes default to mode 1 (note) / 2 (drum, lanes 5–8). GUI mode control offers NOTE/DRUM only.
- **Internal clock**: leave pulse generator, `sendClock`, CC 39/40 (BPM1/2), 59 (ext clock),
  60/80 start/stop. Default `extClock = true`. Not in GUI, not in the socket key set. The stateless
  tick counter (A) must work for both sources so this stays functional.
- Gotcha: `getVel()`/`killHanging()` currently branch on `mode` in ways that assume the old numbering;
  when touching them, keep behaviour identical for modes 3/4.
- Existing latent bugs noticed (fix or leave, decide during implementation): `getVel()` mode-4 `rand()%diff`
  with `diff==0` (div by zero); README lists 1/64 as division 7 but code maps 7 to div 24.

## D. Control socket

force-shadow's host talks to each engine via a Unix socket with `GET`/`SET` keys
(`ctrl_sock=` in `shadow_page.conf`; see `adding-a-page.md` "control socket" sections and
force-acid's `a_*`-style keys as the model). Euclidier only has MIDI CC today.

- Add `--ctrl-sock <path>` (suggest `/tmp/euclidier_ctrl.sock`), handled on a separate thread that
  takes the same mutex as the MIDI callback.
- Keys (proposal): `l<N>_enable|note|div|steps|fill|shift|loop|gate|ch|vel|velh|mode` (N=1..8),
  `preset` (select), `preset_load`, `preset_save`, `rand_lane`, `rand_go`, plus read-only
  `l<N>_pattern` (steps/bits/loop/play-head reply) and `transport` (running/stopped, BPM).
- Each SET routes through the **same code path as the equivalent MIDI CC**, so the two interfaces
  can never diverge. Presets load/feedback on ch 16 continue to work.
- Confirm exact request/reply framing by reading force-acid's socket implementation and
  `adding-a-page.md` before writing (not yet read in detail).
- Engine also needs an `NSMODULE.json`/run script entry so force-shadow's engine on/off button can
  start it (`engine_process_name=euclidier`, `engine_nsmodule_path`, `engine_dirname`,
  `engine_arguments_json` incl. `-v` and `--ctrl-sock`). Current toggle: `SCRIPT-5` in MidiLoop's
  `USER-SCRIPTS.sh` runs `/media/662522/AddOns/Euclidier/euclidier -v`.

## E. Shadow-mode GUI

Page slot: **6** (`ADDON_EUCLIDIER`), file `shadow_page.conf` shipped in the Euclidier AddOns
folder, ideally generated by a script (like force-acid's `gen_shadow_page.py`) because 8 lanes ×
widgets is too many to hand-place. Screen coordinates are the 1280×800 landscape layout used by the
other pages (frames at y≈88..712, 36px side margin).

**Design language**: copy Acid's `style=td3` — chassis-colour background, charcoal boxes/frames,
coloured action buttons, black engine pill, `int_values=1`, `theme_*` keys (see
`~/force-acid/addon/shadow_page.conf` lines 6–34). **Acid = yellow `f5c400` chassis, red `e8341c`
buttons.** **Colours (decided 2026-09-20): pastel lime green chassis (instead of Acid's yellow) with off-white
buttons/ink (instead of Acid's white).** Starting values in the mock-up: chassis `c6e89a`, charcoal boxes
`1f2320`, buttons/ink off-white `f3f0e6`, dim ink `9a9d92`, engine pill black. Tune on a real
`render_preview` render. Mock-up of the options: https://claude.ai/artifact/JPZAgnzzjZLRRfmgGQVuAp
(scratch copy: `scratchpad/euclid-widget-options.html`).

**Widget/tab layout: HYBRID (decided 2026-09-20).** Mock-ups: https://claude.ai/artifact/JPZAgnzzjZLRRfmgGQVuAp
(section "C. Hybrid").

| Tab | Content |
|---|---|
| LANES | All 8 lanes as stacked compact rows (~86px each): lane number + NOTE/DRUM + division, on/off pill, **strip** pattern view (up to 64 cells, loop point marker, cells beyond the loop dimmed, play-head outlined), STEPS/FILL/SHIFT/LOOP readouts. Tap a row = select lane (outline); tap cells = toggle step (see open question). |
| DETAIL | Lane picker 1-8 across the top; selected lane as a large **ring**; 10 parameter tiles with -/+ (STEPS, FILL, SHIFT, LOOP, DIV, NOTE, CHANNEL, GATE, VELOCITY, HUMANIZE) and NOTE/DRUM switch. |
| PRESETS | `list` widget of 128 slots + load/save buttons; randomizer (lane-select enum: ALL / 1-8 / ALL-but-1 / ALL-but-5, plus a RANDOMIZE button). |
| top bar | Engine on/off pill (RUNNING / stopped) + BPM read from the Force clock. |

Needs TWO modes of the new widget in `force_shadow.c`: `euclid mode=strip` (lane rows, up to 64 cells,
optionally two rows of 32) and `euclid mode=ring` (DETAIL). Both take steps/fill/shift/loop/play-head from
`l<N>_pattern`. Mock-up patterns used a simple even spread; real widget must draw the engine's actual
Bjorklund output from the socket, not recompute it. The tab count drops to 3 (+ top bar), so
"LANES 1-4/5-8" from the earlier plan no longer exists. Lane selection is GUI-only state (which lane
DETAIL edits); the socket needs no "selected lane" key if the widget keys are per-lane, but the DETAIL
tiles then need indirection ("selected lane" -> `l<N>_*`). Simplest: add a socket key `sel` and generic
`sel_steps|sel_fill|...` aliases that resolve to the selected lane inside the engine. Decide when writing D.

**Excluded from GUI (still work over MIDI):** velocity sense, receive-notes, notes-in transpose/octave
maps, chord pads, reset-transpose, sync-all, CC modes, internal clock/BPM.
